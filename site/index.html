Case Study

How Elvis was built

  1. Find open data
  2. Load to Snowflake
  3. Model with dbt
  4. Test & document
  5. Serve a product

The problem

Civic open data is a goldmine that's almost unusable raw — pipe-delimited description blobs, string-typed coordinates, no keys. The goal: turn it into something trustworthy and genuinely interesting to look at, using a production analytics-engineering workflow end to end.

The data

Three free datasets from the Las Vegas Valley: the City's public art collection (geocoded points), Southern Nevada Health District restaurant inspections, and fire-prevention inspections of multi-unit residential properties.

Load

A Python script reads each CSV with Polars and batch-inserts it into a Snowflake RAW schema — idempotent, with an --overwrite flag so reloads are safe.

Model

dbt does the heavy lifting across two layers. Staging models rename columns, cast types, and split the art collection's pipe-delimited description field into clean artist, medium, location, address, and ward columns. Mart models shape analytics-ready tables: restaurant grades over time, top violations, and map-ready art points.

Test & document

Every mart carries dbt tests — not_null, unique, and relationship checks — and column-level descriptions that flow straight into the generated docs site and lineage graph. Pre-commit hooks (ruff, ty) keep the Python clean.

Serve

The final mart powers a Streamlit app: a pydeck scatter map of every artwork, filterable by council ward, with a detail panel showing each piece's image, artist, and medium. What started as a string blob is now a product you can click.
